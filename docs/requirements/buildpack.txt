KuBi Developer Build Pack v1.0
1. Architecture
Recommended baseline: modular monolith with strong domain boundaries, API-driven frontend, relational database, background-job processor, object storage and reusable platform engines.
UI → API/BFF → Domain Services → Platform Engines → Database
Platform Engines: Trigger, Workflow, Dependency/Gate, Notification, Exception, Escalation, KPI, Audit

PATIENT → APPOINTMENT → VISIT → PATIENT_PROCEDURE → CONSENT / CLINICAL_DOCUMENT / FOLLOWUP / IMPLANT_USAGE
VISIT → LAB_CASE
CLINIC → ASSET → MAINTENANCE_PLAN / BREAKDOWN
CLINIC → STOCK_LOCATION → STOCK_BATCH → STOCK_TRANSACTION

7. Wireframe Specifications
Today: summary cards (Due Now/Overdue/Alerts), prioritized task cards, Patients Today, Later, verification queue.
Patient 360: medical alert banner; today's doctor/procedure/chair; readiness checklist with exact missing requirement; tabs for clinical, consent, lab, follow-up, communication.
Manager Command Centre: patients, staff, chair readiness, opening/clinical/sterile/lab/inventory scores, critical exceptions, attention queue, patient flow.
Exception Centre: severity tabs, filters, cards showing failure, context, owner, age, SLA and next action.
Owner MIS: clinic health score, eight domains, trends, critical exceptions, repeat failures, root causes, CAPA status.

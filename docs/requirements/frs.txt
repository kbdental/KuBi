KuBi Functional Requirement Specification (FRS) v1.0
1. Purpose & Product Scope
KuBi is a Clinic Operating System designed to reduce dependence on staff memory by converting clinic standards into triggered, assigned, evidenced, verified and escalated workflows.
Operating loop: STANDARD → TRIGGER → ASSIGN → EXECUTE → EVIDENCE → VERIFY → PASS/FAIL → EXCEPTION → ESCALATION → CORRECTION → CAPA → KPI → IMPROVEMENT.
Scope includes appointments, daily operations, clinical readiness, consent, follow-up, sterilization, lab, inventory, implant traceability, equipment, emergency readiness, attendance/leave, competency, conduct, complaints, incidents/CAPA, audits, exceptions, dashboards and audit trails.
2. Design Principles
Exception-based management; role-based experience; configuration before hard-coding; server-side safety and authorization; complete auditability; clinic/location scoping; patient-safety controls cannot disappear silently.

6. Workflow & State Machines
Activity: NOT_DUE → DUE → IN_PROGRESS → COMPLETED → VERIFIED
Failure branches: DUE/IN_PROGRESS → OVERDUE → EXCEPTION; COMPLETED → FAILED_VERIFICATION → EXCEPTION
Appointment: SCHEDULED → CONFIRMED → ARRIVED → WAITING → SEATED → IN_TREATMENT → COMPLETED; alternatives CANCELLED/RESCHEDULED/NO_SHOW
Exception: OPEN → ACKNOWLEDGED → ACTION_IN_PROGRESS → RESOLVED → VERIFIED → CLOSED
CAPA: OPEN → ACTION_IN_PROGRESS → IMPLEMENTED → EFFECTIVENESS_PENDING → EFFECTIVE → CLOSED; ineffective loops back.
7. Business Rules
Critical evidence requirements are enforced server-side. Independent verification cannot normally be performed by the doer. Patient-safety gates require authorized override with reason and audit trail. Failed sterilization cycles cannot release packs. Out-of-service assets cannot be scheduled as available. Expired stock is excluded from usable stock. Implant usage retains patient-to-lot traceability. Restricted activities enforce competency level. CAPA effectiveness is verified before closure where configured.

10. Acceptance Criteria
Opening tasks auto-generate at configured time. Failed critical equipment restricts resource and creates breakdown/exception. Overdue work changes state automatically. Missing mandatory consent makes procedure NOT_READY. Surgery completion creates follow-up. Red-flag follow-up alerts qualified clinical role. Lab overdue creates exception; received cases generate QC. Reorder threshold creates alert/PR. Expired stock excluded. Implant usage records patient/site/SKU/lot. Failed autoclave cycle cannot release packs. PM due generates task. Competency gate blocks invalid independent assignment. Complaint SLA escalates. CAPA closure follows effectiveness verification. Dashboard KPIs drill down and reconcile.
11. MVP & Release Sequence
Phase 1: identity/RBAC, clinic/location, patient/appointment, activity engine, Today, opening/closing, readiness, consent, follow-up, exceptions, notifications/escalations, basic manager dashboard, audit log.
Phase 2: sterilization, lab, inventory, implant inventory, equipment/PM, emergency readiness.
Phase 3: training/competency, complaints, incidents/CAPA, audits, advanced MIS.
12. Definition of Success
Routine work is system-generated; critical work has a single accountable owner; staff work primarily from role-specific Today screens; safety controls cannot disappear unnoticed; exceptions surface before disrupting care; follow-ups are system-generated; recurring failures become root-cause/CAPA learning; owner MIS shows clinic health rather than task clutter.
